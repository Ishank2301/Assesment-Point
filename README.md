## ✨ Overview

Given a load's origin, destination, equipment type, weight, and market conditions, this project predicts the `posted_rate` a carrier would quote. Built for the Spotter ML Engineer assessment on 48,000 labeled historical loads, with final inference run over 12,000 unlabeled loads in `validation.csv`.

**Highlights**

- 📈 **Distance dominates** — correlation with `posted_rate` ≈ 0.91, treated as the anchor feature.
- 🌡️ **Seasonal, not stationary** — rates peak in late spring/early summer. Training data ends in October but targets are needed for December, so seasonality is cyclically encoded (`month_sin` / `month_cos`) to support extrapolation rather than memorization.
- 🧹 **Data quality handled explicitly** — sign-flip errors in `weight` corrected, missing values imputed with month-aware statistics (not global fills), and an anomalous `distance` floor flagged rather than silently patched.
- ⏱️ **Time-based validation** — the train/validation split follows chronological order, not a random shuffle, to honestly test forward-looking generalization into an unseen month.

## 🔍 Approach

### 📊 EDA — Key Findings

| Finding | Detail |
|---|---|
| Distance dominates | `corr(distance, posted_rate) ≈ 0.91` |
| Equipment premium ladder | Dry Van < Flatbed < Reefer (by rate-per-mile) |
| Seasonality | rate-per-mile and `market_index` both peak in late spring/early summer |
| Coverage gap | training data ends **October 2025**; target task needs **December** predictions |

### 🧹 Data-Quality Issues & Fixes

| Issue | Extent | Fix |
|---|---|---|
| Negative `weight` | ~0.6% of rows | `abs(weight)`; original sign flagged in `weight_was_negative` |
| Missing `weight` | 300 rows | train-median imputation; flagged in `weight_was_missing` |
| Missing `market_index` | 374 rows | **month-level** train-median imputation to preserve seasonality; flagged in `market_index_was_missing` |
| `distance` floor anomaly | ~22 rows | short-haul lanes clipped to ~70 mi vs. true haversine distance; flagged via `distance_ratio`, not silently corrected |

### 🛠️ Feature Engineering

- `month_sin`, `month_cos` — cyclical seasonality encoding for extrapolation into December
- `lane` — combined `pickup`–`delivery` categorical
- `haversine_distance`, `distance_ratio` — sanity/anomaly features derived from coordinates
- `equipment` — native categorical (tree-based model)
- `quote_signal` — included only after checking it isn't a leakage proxy for the target

### ✂️ Train/Validation Split

Time-based, not a random shuffle: train on earlier months, validate on later held-out months, since the real task is forecasting a month unseen in training. Exact cutoff and rationale are documented in `notebooks/01_eda.ipynb` and the report.

### 🤖 Model

Gradient-boosted trees (**LightGBM**), evaluated with MAE / RMSE / MAPE on the time-based validation split.

## ▶️ Usage

**1. Train**
```bash
python -m src.train
```
Fits the `FeaturePipeline` and model on `train_test.csv`; saves `models/model.pkl` and `models/pipeline.pkl`; writes metrics and figures to `reports/figures/`.

**2. Predict on `validation.csv`**
```bash
python -m src.predict
```
Loads the saved pipeline (`.transform()` only — no re-fitting) and model, predicts on `data/validation.csv`, merges onto the template by `load_id`, and writes `data/validation_predictions.csv` with columns `load_id,predicted_rate`.

**3. Generate the December prediction chart**
```bash
python score.py
```

**Optional — run tests**
```bash
pytest tests/
```

## 🧭 Key Decisions

The judgment calls that most shape this project's validity:

- **Time-based split over random shuffle** — mirrors the real deployment scenario (forecasting an unseen future month), so the validation score isn't inflated by leaking future information into training.
- **Cyclical month encoding, not one-hot** — lets the model extrapolate into December on a continuous seasonal curve, instead of treating it as a category it never saw during training.
- **Flag, don't silently fix, the `distance` floor anomaly** — preserves the signal for both the model and any reviewer, rather than guessing at a "correct" value for ~22 ambiguous rows.
- **Month-aware imputation for `market_index`** — a single global average would have flattened the seasonal signal the model depends on.
- **`quote_signal` included only after a leakage check** — protects the core assumption the whole evaluation rests on: that validation performance reflects genuine generalization, not a proxy for the target sneaking through.

---

## 🔁 Reproducibility

Random seeds are fixed in `src/model.py`. All imputation statistics (medians, month-level averages) are computed once on the training split inside `FeaturePipeline.fit()` and reused as-is for validation and inference — never recomputed on unseen data.
